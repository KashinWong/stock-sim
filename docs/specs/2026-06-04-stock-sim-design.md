# stock-sim 模拟炒股 Agent Skill — 设计文档

日期：2026-06-04
状态：已确认，待进入实现计划

## 1. 目标

设计一个 Claude Code skill，给 agent 一个虚拟股票账户，让它在 A 股市场进行模拟买卖。要求 agent：

- 自主探索选股策略
- 每日报告选股思路、资金操作、账户盈亏
- 周期性复盘并改进策略

核心约束：模拟交易必须基于**真实行情**，复盘改进必须有**客观归因**，避免把运气当能力。

## 2. 已确认的核心决策

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 数据来源 | 免费行情 API，多源兜底 | 确保数据通畅，不依赖单一源 |
| 市场范围 | A 股为主 | T+1、涨跌停、整手、税费规则 |
| 账户存储 | JSON + Markdown 文件 | 人可读、可 git 版本管理、零依赖 |
| 运行节奏 | 定时自动运行（收盘后） | 见 §6 调度说明 |
| 策略形态 | 自然语言策略文档 | 符合 LLM 推理优势，可读可迭代 |
| 操作记录 | record.md + operations.jsonl 两份 | 人读叙事 + 机读结构化 |

额外加入的两个防自欺机制：

- **业绩基准对比**：每日报告强制并列账户收益率 vs 沪深300同期收益率，复盘时据此区分 alpha 与 beta。
- **策略改动需举证**：每处策略修改必须记录「理由 + 基于哪几笔交易的证据」，避免追逐噪声。

## 3. 文件结构

工作目录建议 `~/.claude/stock-sim/`：

```
stock-sim/
├── SKILL.md                    # skill 主文件，按场景分段的工作流
├── scripts/
│   └── quote.py                # 多源兜底行情，对 agent 暴露统一接口
├── account/
│   ├── account.json            # 现金、总资产、持仓、累计盈亏（唯一真相源）
│   └── trades.jsonl            # 逐笔成交明细（只追加，永不改）
├── strategy/
│   └── strategy.md             # 自然语言策略文档（agent 自迭代，保留历史）
└── journal/
    ├── record.md               # 操作总账叙事（人读，按日追加）
    ├── operations.jsonl        # 结构化操作流（机读，按日追加）
    ├── YYYY-MM-DD-daily.md      # 单日报告：选股思路 + 操作 + 盈亏 vs 基准
    └── YYYY-MM-DD-review.md     # 复盘：归因 + 策略改进举证
```

## 4. 关键组件

### 4.1 行情脚本 `quote.py`（隔离与兜底）

- 内置多数据源，按优先级 fallback：AKShare → Tushare → 新浪/腾讯财经。任一成功即返回。
- 对 agent 暴露稳定接口（命令行子命令或函数）：
  - 查实时价（单只 / 批量）
  - 查日线（历史 K 线，供策略指标计算）
  - 查指数（沪深300，作基准）
- 接口不稳/限频问题锁在脚本内（重试、当日数据缓存），agent 不直接碰 API 细节。

### 4.2 账户状态（原子更新）

- `account.json` 是唯一真相源：现金、总资产、持仓列表（代码/数量/成本价/可卖数量）、累计盈亏。
- 每次交易流程：校验现金或持仓是否充足 → 按 A 股规则成交（T+1、100 股整手、印花税 + 佣金）→ 更新 `account.json` 并追加一条 `trades.jsonl`。
- `trades.jsonl` 只追加不修改，可完整审计。

### 4.3 策略文档（受约束的进化）

- `strategy.md` 用自然语言描述选股逻辑与买卖规则。
- 复盘修改时要求记录改动理由与交易证据。
- 保留历史版本（git 或带日期备份），可回看策略演变。

### 4.4 操作记录（双份同步）

- `record.md`：按日追加的高层操作叙事，人翻一份文件即可看完整时间线。
- `operations.jsonl`：结构化字段（日期、动作类型、标的、理由、盈亏），可机读统计。
- 两者在每次操作时**同步追加**，保持一致。

## 5. 场景工作流

### 场景 A — 每日选股交易（收盘后触发）

1. `quote.py` 拉持仓股最新价 + 沪深300指数 → 刷新 `account.json` 市值与盈亏。
2. agent 读 `strategy.md`，按策略扫描候选股，拉行情验证信号。
3. 输出选股思路 → 按 A 股规则模拟下单 → 更新 `account.json` + 追加 `trades.jsonl`。
4. 同步追加 `record.md` + `operations.jsonl`。
5. 生成 `YYYY-MM-DD-daily.md`：今日操作、账户盈亏、**vs 沪深300**。

### 场景 B — 复盘改进策略（周期性，如每周/月底）

1. 读近期 trades 与 daily 报告，统计胜率、盈亏比、**超额收益（vs 基准）**。
2. 归因：跑赢/跑输是选股 alpha 还是大盘 beta？哪些交易验证或证伪了策略？
3. 改 `strategy.md`，每处改动记录理由 + 证据（基于哪几笔交易）。
4. 生成 `YYYY-MM-DD-review.md`。

### 场景 C — 查账（随时）

- 读 `account.json` 输出：总资产、持仓明细、累计收益率 vs 基准、近期操作摘要。

## 6. 调度说明（重要）

CronCreate 的定时任务只在 Claude 会话空闲时触发，默认 7 天过期、会话关闭即失效，不适合长期「每日收盘后自动跑」。更可靠的方式是用现有的 `auto-coder-cli` 自动化引擎在系统 crontab 中调度，于每个交易日收盘后调用本 skill 的场景 A。本设计先实现 skill 本体与文件结构，调度接入作为后续步骤标注。

## 7. A 股交易规则（成交校验需遵守）

- T+1：当日买入次日才可卖。
- 整手：买入数量为 100 股整数倍。
- 涨跌停：成交价不超出当日涨跌停区间（约 ±10%，ST 股 ±5%）。
- 费用：佣金（双向，含最低收费）、印花税（卖出单向）、过户费。
- 交易时间：仅交易日有效行情；非交易日不开仓。

## 8. 非目标（YAGNI）

- 不做美股、不做实时盘中高频交易。
- 不做可执行代码策略 / 结构化参数策略。
- 不做真实下单，纯模拟。
- 不做多账户并行（先单账户）。
